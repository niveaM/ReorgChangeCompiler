Reorg Change Compiler

Paste a reorg announcement as it arrived. The page redacts PII, has an LLM read it into a typed change set, checks it against five systems of record, and compiles the ordered, gated runbook that propagates it, including the step a person has to key by hand. Systems are simulated with a seeded fictional company; every rule and check is real code.

04

  

    
Validate

    
Deterministic checks against the systems of record, re-run on every edit. Blockers stop the pipeline. Approval items route to a named person. The validator also derives the work nobody wrote down: budget that should follow people, GL remaps and closing the cost center a merge empties.

05

  

    
Approve

    
Gates are chosen by what the change touches. Gate-1 always applies; no risk level skips it. Each signature covers the gate, the signer, the change-set version and a hash of the systems at signing. Editing the change set voids every signature, and so does drift in the systems.

    

  






  
06

  

    
Propagate

    
The runbook, compiled from the change set. Order is fixed by phase and each phase says why. A step unlocks only when every earlier phase is done and its gates are signed. Before every step, the live systems are hashed and compared with the state the plan expects; any outside change stops the run. Allocation has no API, so those steps issue a hash-bound ticket, wait for the person who keys it, and complete only after a second person verifies it.

    

    

    

    

  






  
07

  

    
Reconcile

    
Independent of the plan: reads all five systems and checks the invariants that today only fail weeks later in a financial report. Try keying an allocation rule that sums to 90% and see it caught here.
